dsh/index.js · CodeGraph DSH plugin · 18 files

把 Mermaid 变成一张 可点击的图

CodeGraph 的 DSH 插件只做一件事：把 agent 生成的 Mermaid 和位置表， 变成一张能点回源码的图。它不碰业务逻辑，也不在浏览器里做运行时编译。

input

Mermaid + 位置表

节点、边、消息各自对应一条真实源码位置；这是导航的协议。

build

校验后再构建

先跑 validate，再把模板、样式、源码和运行时打包成单个 HTML。

view

图 tab 负责展示

卡片打开右侧栏；点击图元，由宿主打开对应源码行。

02 · The entry

入口只是一个 tool call

它先确认 repo 在工作区内，然后把 Mermaid 和位置表交给 buildDiagram。

1
限定工作区
repo 不能跑出 session workspace。
2
只传语义输入
Mermaid + 位置表，不传渲染细节。
3
交给管线
校验、构建、错误修复都在下一层。
注意：tool 层不直接拼 HTML；它只负责边界和路径。

03 · Source link

为什么点一下就能到源码

图里存的是 file:line，不是一段被复制进 HTML 的代码；点击后由宿主决定打开哪里。

点击 → 桥接 → Harness 源码 pane；浏览器里则打开右侧源码抽屉。
A
位置表是唯一事实
节点/边/消息都映射到真实语句。
B
渲染与导航解耦
图只负责发位置；谁打开、怎么开由宿主决定。
C
内容可独立打开
没有 DSH 时，页内源码抽屉就是 fallback。

实现锚点：右侧栏 iframe 桥接

04 · Boundaries

三个容易误解的边界

图看起来很确定，但它的可信度来自“位置可核对”，不是“解释自动正确”。

validator

校验 ≠ 语义正确

校验器能检查语法、覆盖、路径和行号，不能证明“这段代码真的实现了这个业务含义”。

source

源码会变

产物是当前 checkout 的快照；代码改动后，行号可能漂移，需要重新构建。

content

讲解仍需证据

每个关键判断都要回到代码/测试；推断要标注，业务背景缺失时不要脑补。

最危险的情况：图能点、页面好看、但一个关键业务假设是模型猜的。源码链接不能替代证据。

05 · 自测

两道题，检查你是否真的理解

先自己回答，再点选项或“查看答案”。

Q1. 一次构建里，哪一步应该发生在“把产物移动到最终目录”之前？
答案：B。校验失败不能产出半成品，所以校验发生在临时目录；只有通过后才 rename 到最终输出目录。
Q2. 为什么图里存 file:line，而不是直接把源码抄进 HTML？
参考：位置是可核对的协议，源码是事实来源。直接抄代码容易过期、抄错，也无法让宿主打开完整文件；存位置则可以随时打开当前源码。
